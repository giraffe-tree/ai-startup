# 安全合规清单

**项目**: DocFlow AI
**日期**: 2026-05-26
**适用场景**: 律所客户（处理客户合同、案件文件等高度敏感数据）

---

## 背景：律所客户的合规压力

律所客户在评估 SaaS 工具时面临双重约束：
1. **律师职业保密义务**（Attorney-Client Privilege）：律所对客户信息负有法定保密义务，工具选型需能证明数据不被第三方获取。
2. **企业客户审查**：律所的企业客户（上市公司、金融机构）越来越要求供应链工具提供 SOC 2 报告。

当前阶段目标：不需要立即获得 SOC 2 认证（18-24 个月工程），但需要做到"如果被律所 IT 部门审查，能通过基本尽职调查"。

## 一、代码层面漏洞与合规差距

| 检查项 | 当前状态 | 要求 | 优先级 |
|--------|---------|------|--------|
| 传输加密（TLS 1.2+） | ✅ Vercel 默认启用 | 必须 | — |
| 存储加密（PostgreSQL at-rest） | ⚠️ 依赖 Supabase 默认配置，未验证 | 必须 | P0 |
| 文件存储加密（PDF 原文） | ❌ S3 bucket 未开启 SSE-S3 | 必须 | P0 |

**P0 修复**：确认 Supabase 存储加密已启用；S3 bucket 开启 SSE-S3（1 行配置，30 分钟）。

### 访问控制

| 检查项 | 当前状态 | 要求 | 优先级 |
|--------|---------|------|--------|
| 多租户数据隔离 | ❌ 未验证（见 tech-debt.md P0-1）| 必须 | P0 |

### OpenAI 数据处理

**关键风险**：律所客户最常问"你们把合同发给 OpenAI，OpenAI 会用来训练模型吗？"

**当前状态**：使用 OpenAI API（非 Consumer 产品），默认不用于训练，但未签署数据处理协议（DPA）。

**修复项**：
- [ ] 与 OpenAI 签署 Enterprise DPA（需申请 OpenAI 企业账号，约 1-2 周）
- [ ] 隐私政策明确写明"合同内容通过 OpenAI API 处理，依据 OpenAI Enterprise DPA 不用于模型训练"
- [ ] 未来可选：部署私有化模型（Azure OpenAI Service）作为企业客户选项，消除顾虑

## 二、企业买家会要求的控制措施

### 审计日志（Audit Log）

律所合规部门要求能回答："谁在什么时间查看了哪份合同？"

**需要记录的事件**：

```
用户登录 / 登出
合同上传（含文件名、上传者、时间）
合同查看（含查看者、时间）
合同分析触发
合同删除（含操作者，保留 30 天）
用户权限变更
API 密钥创建/撤销
```

**当前状态**：❌ 完全没有审计日志。

**修复方案**：
- 新建 `audit_logs` 表，结构：`(id, org_id, user_id, action, resource_type, resource_id, metadata JSONB, created_at)`
- 在关键操作后写入（用数据库触发器或应用层 middleware）
- 暴露给律所管理员的审计日志查询界面（P1 功能）
- 日志保留 2 年（律所合规要求）

**工作量**：数据库结构 1 天，接入各操作点 2 天，管理界面 3 天。

### 访问管理

| 能力 | 当前状态 | 律所要求 |
|------|---------|---------|
| 基于角色的权限（管理员/普通用户）| ❌ 所有用户权限相同 | 必须：管理员可管理成员和查看所有合同 |
| SSO / SAML 集成 | ❌ 无 | 大型律所（10 人以上）的标配要求 |
| 强制多因素认证（MFA）| ❌ 无 | 企业客户要求 |
| 会话超时 | ⚠️ 默认 7 天，太长 | 律所建议 8 小时 |

**优先修复**：基础角色权限（管理员/成员）是正式发布前必须有的功能。MFA 和 SSO 可在签下第一个 10 人以上客户时作为交付条件。

### 数据驻留与删除

| 要求 | 当前状态 | 处理方式 |
|------|---------|---------|
| 数据存储在哪个地区？| us-east-1（Supabase 默认）| 在隐私政策中明确说明 |
| 客户退订后数据如何处理？| ❌ 无流程 | 需要：退订后 30 天发删除确认，90 天内完全清除 |
| 律所要求导出全部数据 | ❌ 无 | 需要：提供合同 PDF 和分析报告的批量导出 |

## 三、GDPR 合规（针对有欧洲客户的情况）

当前客户均为美国律所，GDPR 暂时不是主要约束。但如果有客户在欧洲处理业务或有欧洲籍当事人数据，需要注意：

- [ ] 隐私政策包含数据处理合法性基础（合同履行 / 合法利益）
- [ ] 用户可申请数据导出和删除（Right to Erasure）
- [ ] 数据处理记录（ROPA）—— 中期需求

**实用建议**：现阶段在服务条款里写明"仅服务美国客户"，显式排除 GDPR 约束，待业务扩展到欧洲时再系统处理。

## 五、给律所客户的合规沟通模板

当律所 IT 或合规部门询问时，可以提供以下标准回答：

> **数据安全**：所有数据传输采用 TLS 1.2+ 加密，静态数据采用 AES-256 加密存储。
>
> **数据隔离**：每个律所的数据完全隔离，不同客户之间无法互相访问。
>
> **AI 处理**：文件通过 OpenAI Enterprise API 处理，依据 Enterprise 数据处理协议（DPA），您的数据不会用于 OpenAI 的模型训练。
>
> **审计日志**：系统记录所有文件访问和操作，管理员可查看完整操作记录。
>
> **数据删除**：您可随时申请删除所有数据，退订后 90 天内完成全量清除，并提供书面确认。
